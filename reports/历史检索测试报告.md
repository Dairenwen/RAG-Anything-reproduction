## 解析、检查与建库是不同阶段

```text
data/原始 PDF
    └─ parse → parsed/文字、图片、表格、公式
                  └─ inspect → 核对路径、源文件和资源哈希
                                  └─ ingest → storage/知识图谱、向量索引和文档存储
                                                   └─ query / batch → runs/检索证据、答案和运行记录
```


| 阶段       | 命令              | 做什么                                                              | 本地输出                  |
| ---------- | ----------------- | ------------------------------------------------------------------- | ------------------------- |
| 解析       | `parse`           | MinerU 提取正文、图片、表格、公式；尚未生成 RAG 实体关系与向量索引  | `parsed/<doc-id>/`        |
| 检查       | `inspect`         | 校验 PDF、内容列表和资源的路径与哈希；内容是否准确仍需对照原文检查  | 终端检查输出              |
| 建库       | `ingest`          | 调用文字/视觉模型理解内容、抽取实体关系；调用 Ollama 编码向量并保存 | `storage/<kb>/`           |
| 检索与问答 | `query` / `batch` | 读取知识库，保存检索证据、答案、图片输入数、耗时与模型用量          | `runs/<时间戳_随机标识>/` |

### 为什么解析先选 CPU

`--device cpu` 只控制 MinerU 的本地 PDF 解析。本轮固定版本为 MinerU 3.4.1，已有这篇论文在 CPU 上成功解析的记录，因此先用它作为已验证的运行路径。

本机检查表明 PyTorch 的 MPS 可用，当前解析器也接受 `--device mps`。MPS 是 PyTorch 在 Mac 上使用 Apple GPU 的设备接口；若要尝试 GPU 解析，在尚未创建目标解析目录时，可以把原解析命令中的 `--device cpu` 改为 `--device mps`。如果目录已经存在，应保留已有结果并使用新的 `doc-id` 做对照，同时让后续建库和问题文件的文档 ID 与之匹配。MPS 在本轮环境中尚未做完整 PDF 解析验收，不能预先保证加速幅度或结果一致性。[PyTorch MPS 文档](https://docs.pytorch.org/docs/stable/notes/mps.html)

DeepSeek 的文字与视觉推理在官方服务端运行；Ollama 的 embedding 推理由 Ollama 自己管理，`--device cpu` 不会把它们限制在本机 CPU。需要查看 Ollama 实际使用的处理器时，模型运行期间执行 `ollama ps`。

## 命令说明


| 命令                   | 作用                                                  | 外部模型 API                  |
| ---------------------- | ----------------------------------------------------- | ----------------------------- |
| `check`                | 检查包版本和解析命令                                  | 不调用                        |
| `rerank-check`         | 用两段文字检查已下载的本地 BGE 重排模型；结果只输出到终端 | 不调用外部 API，也不读取知识库 |
| `probe`                | 验证文字、关键词、embedding，可选择图片；支持`--role` | 文字/视觉调用，向量在本地     |
| `sample`               | 从论文现有解析中选取四类内容                          | 不调用                        |
| `smoke`                | 真实模型小样本建库、重启、检索与视觉回答              | 调用                          |
| `parse`                | 本地解析 PDF，首次可能下载解析模型                    | 不调用已配置的文字/视觉 API   |
| `inspect`              | 核对解析内容、源 PDF 和图片哈希                       | 不调用                        |
| `ingest`               | 从已检查的解析结果建库                                | 调用                          |
| `query --context-only` | 结构化检索，不生成答案                                | 关键词与 embedding 仍可能调用 |
| `query`                | 诊断检索与文字生成                                    | 调用                          |
| `query --vlm`          | 诊断检索与视觉增强生成                                | 调用                          |
| `batch`                | 串行运行问题文件，保存逐题结果，异常时停止            | 调用                          |

### 检索与问答选项：`query` / `batch`

| 选项 | 含义与用法 | 默认值或要求 |
| --- | --- | --- |
| `--kb` | 选择要读取的知识库，对应 `storage/<kb>/`。本轮写 `--kb handson-qwen4096-v1` | 默认 `pilot-v1` 是历史名称；本轮应显式指定 |
| `--question` | 单个问题，用引号包住完整句子 | `query` 必填 |
| `--questions` | 批量问题文件路径，例如 `questions.handson.jsonl`；文件中的 `doc_id` 必须与知识库内文档匹配 | `batch` 必填；不能用 `--question` 替代 |
| `--mode` | 选择检索方式：`naive`、`hybrid` 或 `mix`，区别见下表 | 默认 `mix` |
| `--context-only` | 只检索并保存证据，不生成最终答案；仍可能调用模型提取关键词，并调用 Ollama 编码问题 | 默认不启用；启用后 `answer` 为 `null` |
| `--vlm` | 生成答案时，将检索到的可用图片交给视觉模型，适合图表题 | 默认不启用；与 `--context-only` 同用时不会进入视觉答案生成 |
| `--rerank` / `--no-rerank` | 开启／关闭本地 BGE 内容块重排；不需要重新建库 | 默认关闭，也可由 `ENABLE_RERANK` 配置；命令选项优先 |
| `--timeout` | 单个问题的最大等待秒数；批量执行时对每题分别计时 | 默认 `300`，必须为正整数 |
| `-h` / `--help` | 查看该命令接受的选项，例如 `python reproduce.py query --help` | 不运行检索、不调用模型 |

| 检索模式 | 通俗说明 |
| --- | --- |
| `naive` | 按向量相似度找内容块，不走知识图谱检索 |
| `hybrid` | 结合实体和关系两路图谱检索，再取关联的内容块 |
| `mix` | 在 `hybrid` 的基础上加入内容块向量检索，合并两类证据 |


### 解析、建库和接口检查选项

| 选项 | 适用命令 | 含义与默认值 |
| --- | --- | --- |
| `--pdf` | `parse` | 必填，原始 PDF 路径；本轮使用 `data/RAG-Anything_arXiv_2025.pdf` |
| `--doc-id` | `parse`、`inspect`、`ingest`、`sample`、`smoke` | 文档解析目录的标识；前三个命令必填，本轮为 `rag-anything-handson-v1`；`sample` / `smoke` 默认 `rag-anything-smoke-v1` |
| `--device` | `parse` | PDF 解析设备，可选 `cpu`、`mps`、`cuda:0`；默认及本轮设置均为 `cpu` |
| `--kb` | `ingest`、`smoke` | 知识库名称；`ingest` 默认 `pilot-v1`，本轮显式写 `handson-qwen4096-v1`；`smoke` 默认 `smoke-qwen4096-v1` |
| `--source-doc-id` | `sample` | 从哪个已解析文档抽取四类样本；默认 `rag-anything-v1` |
| `--role` | `probe` | 选择 `all`、`text`、`vision` 或 `embedding`，默认 `all`；`text` 检查包含文字回答和 DeepSeek 关键词 JSON |
| `--image` | `probe` | 视觉接口测试的图片路径，建议使用绝对路径；`--role vision` 时必填，`all` 未提供图片时不执行视觉检查 |
| `--timeout` | `parse`、`ingest`、`smoke` | 最大等待秒数：默认分别为 `1800`、`3600`、`900`，必须为正整数 |

`--doc-id` 选解析文档，`--kb` 选知识库，两者不能互换。
