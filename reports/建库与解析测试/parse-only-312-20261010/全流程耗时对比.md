## 模型调用配置详情

本次本地建库采用视觉、文本两个角色回调；框架文本请求并发上限为 2，图片描述按对象串行处理。Ollama 服务配置为 `OLLAMA_NUM_PARALLEL=1`，已观察到的 llama.cpp 运行器为单执行槽。三组请求记录中，视觉与文本调用的重叠时间均为 0 秒。因此，本次属于分角色、按阶段执行的建库测试。

## 2. 实际调用顺序与职责

1. **PDF 解析**：MinerU CPU pipeline，`auto` 模式，公式、表格解析开启。使用 PP-DocLayoutV2、UniMERNet Small、PP-OCRv6、SLANet Plus／UNet；不调用上述 Ollama 视觉、文本模型。此前建库复用已校验的解析结果；后来的三次计时只重新解析，没有再次建库。
2. **正文入库**：先处理正文，完成该阶段后再进入多模态处理；正文的实体关系抽取、摘要与合并使用文本回调。
3. **多模态描述**：27 个对象按对象逐个处理。15 张图片通过视觉回调发送图片和提示词；6 个表格使用解析后的表格内容调用文本回调，6 个公式使用解析后的公式内容调用文本回调。表格和公式并未统一发送给视觉模型。
4. **描述入库与图谱合并**：多模态描述生成完成后，再使用文本回调抽取知识、合并图谱，使用向量模型编码文本、实体和关系。

图片请求通过 OpenAI 兼容的聊天接口发送，内容含文字提示和 Base64 图片。文本请求使用同一类聊天接口，向量请求使用 embeddings 接口。生成调用使用非流式返回。

## 3. 并发配置与实际观察

| 层级／项目 | 配置 | 本次三组实际观察 |
|---|---|---|
| 文本模型请求 | `LLM_CONCURRENCY=2`，传入 `llm_model_max_async=2` | 文本请求同时等待峰值均为 2 |
| 文件／入库任务 | `max_parallel_insert=1` | 每组只处理一份 PDF |
| 多模态对象描述 | 框架以 `max_parallel_insert` 创建信号量，本次为 1 | 图片描述请求同时等待峰值均为 1；表格、公式描述也按对象串行 |
| 视觉与文本同时调用 | 按官方阶段先后执行 | 两种角色的请求区间重叠均为 0 秒 |
| 向量请求 | 框架并发上限 8 | 同时等待峰值均为 4 |
| 向量批量大小 | `embedding_batch_num=10` | 最大一次返回 10 个向量；多数实体／关系调用返回 1 个 |
| Ollama 服务并行 | 服务日志记录 `OLLAMA_NUM_PARALLEL=1`；测试运行器未改写此服务参数 | 已记录的 llama.cpp 模型加载显示 `n_seq_max=1` |
| Qwen3.8 MLX 后端 | 通过同一个 Ollama 服务调用 MLX 运行器 | 未保存其内部批处理／同时推理的细粒度记录 |
| 历史官方 API 后端 | 客户端配置的文本并发上限为 2 | 未保存完整调用时间线；服务端实际推理并行度未知 |

这里的“同时等待”包含排队、网络请求和推理。框架提交两个文本请求，并不能证明模型后端同时推理两个请求。Ollama 的并行参数也不等于允许驻留的模型数；组 2 运行快照同时有文本、视觉和向量三个模型驻留，但请求记录仍没有视觉与文本调用重叠。

## 4. 本地三组统一参数

| 项目 | 实际配置 |
|---|---|
| 生成模型上下文 | `num_ctx=16384`；通过基于已安装模型创建的别名设置 |
| 单次生成输出上限 | `max_tokens=8192`，对视觉、文本均生效 |
| 温度 | `temperature=0` |
| 思考请求 | `reasoning_effort=none` |
| 分块大小／重叠 | 1200／100 tokens |
| 摘要语言 | English |
| 向量模型／维度 | `qwen3-embedding:latest`／4096 |
| 向量输入长度配置 | `max_token_size=8192` |
| 向量维度请求参数 | 不发送 `dimensions`；由实际返回的 4096 维向量验收 |
| 文本、视觉 HTTP 请求等待 | 600 秒 |
| 向量 HTTP 请求等待 | 90 秒；接入函数中的 `client_configs` 固定为 90 |
| 框架函数等待 | 文本和向量均为 600 秒；日志同时记录 worker 等待 1200 秒、健康检查 1215 秒 |
| SDK 重试 | 视觉、文本设置 `max_retries=0`；向量沿用 SDK 默认重试 2 次 |
| 框架重试 | 原有装饰器保留，符合条件的错误最多尝试 3 次；不能将 SDK 重试为 0 理解为完全没有重试 |
| 整组建库等待上限 | 14400 秒（4 小时） |
| 通用 LLM 缓存 | 关闭；实体抽取缓存保留，每组使用全新知识库，不共享前一组建库缓存 |
| 重排 | 关闭 |
| 测试顺序 | 3→1→2；分别运行，各组不同时建库 |

`EMBEDDING_TIMEOUT=600` 设置的是框架等待层，未覆盖向量 HTTP 客户端的 90 秒配置。

三个生成标签均从已有模型创建，只设置 16384 的上下文，未更换权重。向量模型未创建上下文别名，组 2 运行快照记录其上下文为 40960，因此 16384 的统一限制仅适用于生成模型。

历史 DeepSeek 的清单可确认温度由原接入函数设置为 0、文本并发为 2、分块为 1200／100、摘要语言为 English、向量模型为本机 4096 维 Qwen3 Embedding。其思考通过 `thinking.type=disabled` 关闭，原生成 HTTP 等待为 90 秒；未记录 16384 的上下文限制和 8192 的输出上限，也未应用本地正式测试的 SDK 零重试覆盖。因此历史 API 结果应作为历史参考，不能视为所有调用参数完全一致的同轮对照。
